3출처 · 이용조건

3.1 출처 표기

모든 데이터의 출처는 제주특별자치도, 제주데이터허브(jejudatahub.net)이며, 1048은 제주빅데이터센터가 제공한 자료다. 화면의 "수록 기간과 출처", 답마다 붙는 근거표·한계, 최종 제안서, 이 문서에 출처를 적는다. 제주빅데이터센터 이용지침에 따라 결과물에는 다음 문구를 넣는다.

본 자료는 제주빅데이터센터에서 제공하는 자료를 활용한 것이며, 연구결과는 제주특별자치도 및 제주테크노파크와 관련이 없음을 밝힙니다.

3.2 이용조건과 대응

허브와 센터 데이터에는 「데이터 이용약관」(제주데이터허브·제주빅데이터센터 공통, 2021-01-01 시행)과 제주데이터허브 「이용약관」이 적용된다. 아래는 조항별로 머물멍이 한 일이다 (약관 원문은 허브의 /api/policy에서 2026-11-19에 확인).

조항내용머물멍의 대응
데이터 이용약관 제7조제공기관 정보임을 표시하는 출처표시 의무화면·제안서·제출 문서에 출처 표기 (3.1절)
제7조 센터 이용지침 8호보고서·발표자료 등 결과물에 출처 문구를 넣고 30일 안에 제공기관에 제출제출 문서에 문구를 넣었다. 제공기관 제출은 팀이 대회 결과물과 별도로 확인해 이행한다
제5조 4호받은 정보를 서비스 플랫폼 없이 그대로 제3자에게 유료로 제공·공유 금지원자료를 배포하지 않는다. 화면에는 분석 결과(집계)만 보여 준다
제5조 7호OpenAPI 인증키의 무단 양도 금지프로젝트 키는 각자 발급해 .env에만 둔다. 저장소·실행 이미지에서 제외 (.gitignore · .dockerignore, 테스트로 확인)
제5조 8·9호특정 개인·법인 식별 시도, 개별자료 누설 금지집계 통계만 쓴다. 원자료 행 단위 출력이 없고, 반출 규칙에 식별 컬럼 금지를 둔다
제5조 10호, 이용지침 6호센터 승인 없이 산출물 반출·공표 금지, 반출은 신청·승인 후센터 모드는 반출 규칙(최소 셀 5, 식별 컬럼 금지)을 통과한 집계표만 반출 신청 대상으로 둔다
제8조 · 제10조통계정보 상업적 활용 가능(예외 제외), 정보는 무상 제공비영리 공모전 출품. 데이터 비용 없음
이용약관(사이트)서비스로 얻은 정보를 사전 승낙 없이 복제·배포하거나 타인에게 제공 금지허브 수집본과 그 CSV 내보내기를 저장소·이미지에 넣지 않는다. 필요한 사람은 각자 키로 받는다

3.3 개인정보와 외부 전송

  • 쓰는 자료는 모두 집계 통계다. 유동인구는 통신 데이터로 추정한 읍면동·일 단위 집계이고, 카드는 업종·월 단위 집계다. 개인을 식별할 수 있는 항목은 없다.
  • Claude에는 질문, 규칙이 만든 설명 초안, 동네별 집계 지표(최대 40행)만 보낸다. 보낼 내용을 "전송 미리보기"로 먼저 보여 주고 동의한 세션만 보낸다.
  • 네이버 지도 API에는 읍면동·거점의 대표 좌표와 사용자가 입력한 주소만 보낸다. 데이터 값은 보내지 않는다.

4전처리 흐름

4.1 수집

  • 허브에서 데이터마다 "프로젝트 담기"를 한 뒤 Open API(open.jejudatahub.net/api/proxy/{dataKey}/{projectKey})로 받는다. 쪽당 최대 100행(number, limit), 응답은 {totCnt, hasMore, data} 형식이다 (2026-11-16 실제 호출로 확인).
  • 허브 프록시가 자주 502를 돌려줘서 한 쪽에 10번까지 다시 보낸다. 하루 상한(데이터마다 1,000건, 실패도 셈)에 닿으면 멈추고 다음 날 받은 쪽 다음부터 이어 받는다.
  • 일 단위 3종은 쿼터를 아끼려고 달마다 정한 날짜만 받는다 (유동인구 1·9·17·25일, 버스 9·25일). 파일 데이터(1048)는 허브에서 내려받아 data/hub/card_biz/에 둔다.

4.2 표준화

항목규칙
날짜 · 월YYYYMMDD·YYYYMM·YYYY-MM 등을 날짜로 바꾸고, 월 자료는 매월 1일로 맞춘다. 없는 날짜(2월 30일 등)는 비운다
숫자글자로 온 숫자를 정수·실수로 바꾸고, 숫자가 아닌 값은 비운다
장소시군구 + 읍면동 이름을 행정동 코드 8자리로 통일한다. 법정동 이름(예: 법환동 → 대륜동)과 별칭도 참조표로 연결한다
인구 단위허브 유동인구는 하루 24개 시각 값의 합이라 24로 나눠 "시간 평균 인구"로 쓴다. 24로 나눈 읍면동 거주인구가 주민등록 인구의 75~100% 수준임을 확인했다 (제주 전체 약 49만 명)
연령 · 성별연령은 10세 단위(청년 = 20·30대), 성별은 남·여로 맞춘다
업종 → 테마허브 카드 업종 9종과 1048의 업종 43종을 6개 테마(식음료, 숙박, 쇼핑·소매, 교통, 문화·레저, 기타)로 묶는다 (ref_theme.csv)
국적 · 방문목적 · 노선국적 12종, 방문목적 9종, 표준 노선 번호로 맞춘다

4.3 품질 처리

처리규칙과 결과
연결 못 한 이름 · 날짜행정동으로 연결하지 못한 이름과 날짜 변환 실패 행은 빼고 적재 보고서(status의 issues)에 남긴다. 실데이터 적재에서는 0건이었다
일수가 모자란 달한 달에 기준 일수 미만인 달은 지표에서 뺀다 (샘플 20일, 허브는 달마다 며칠만 받아 2일)
작은 표본기준 인구(직전 기간 청년 거주 일평균)가 100명 미만이면 배지로 표시하고 추천·자동 선택에서 뺀다
작은 비중중국인 테마 중 직전 기간 비중이 1% 미만인 테마는 증가율을 빼고 금액만 보여 준다 (예: 기타 0.04% → +3,142.7%로 보이던 착시). 국적은 비중 3% 미만을 성장률 순위에서 뺀다
기간 겹침함께 쓰는 지표의 기간이 겹치지 않으면 규칙을 적용하지 않고 "함께 볼 수 없음"으로 답한다
오래된 자료 · 단위 대체3년보다 오래된 자료는 문장에 기간을 붙인다. 읍면동 값이 없어 지구·제주 전체 값을 쓰면 한계에 그렇다고 적는다

4.4 비교 기간

최근 12개월(P1)과 직전 12개월(P0)을 비교한다. 두 기간 중 유효한 달이 9개월보다 적으면 전년 동월 비교(자료 끝 3개월)로 바꾸고 그 사실을 표시한다.

4.5 적재와 조회

  • 데이터 모드마다 PostgreSQL 스키마 하나(synthetic · hub · center)에 표준 테이블 8개, 월 집계 3개(m_pop_kor_emd_month 등), 참조표 ref_*, 수록 기간·행 수 meta_*를 만든다.
  • 분석 도구는 읽기 전용으로만 붙는다. LLM이 쓴 SQL도 SELECT 한 문장, 허용 테이블, 행 수·시간 제한을 통과해야 실행한다.
  • 새 데이터는 테이블 설명 파일(YAML) 한 장을 더하면 같은 경로로 적재된다.

5분석 흐름: 지표 · 산식 · 규칙

모든 지표는 SQL로 계산하고, 답마다 실행한 SQL과 산식을 함께 보여 준다. 기준값은 backend/config/settings.yaml, 제안 규칙은 playbook.yaml에 있어 코드 없이 바꿀 수 있다.

5.3 3단계 · 어떻게 오게 하나

지표산식
입도객 시나리오기준선(전년 동월 실적) × (1 + ε × 국내선 공급 변화율). 공급 변화율 기본 −10%, 탄력성 ε 기본 1.0이며 ε 0.5 · 1.0 · 1.5를 늘 함께 보여 준다
노선 관광 민감도 βln(노선 월 이용자)를 ln(개별여행 입도객)에 회귀한 기울기. 12개월 이상, R² 0.5 이상만 "관광 민감 노선"으로 채택
코스 · 접근성 공백거점 6곳(공항·항만·터미널)에서 동네까지 직행 또는 환승 1회로 닿는 노선. 닿지 않는 거점은 접근성 공백으로 표시 (코스 최대 3개)
시나리오는 예측이 아니라 가정에 따른 계산이다. 감편률과 탄력성은 사용자가 바꾸는 가정값이며, 모든 방문목적에 같은 비율을 적용한다. β는 함께 움직인 정도를 요약한 값으로 원인을 뜻하지 않는다. 머물멍은 어느 단계에서도 인과를 단정하지 않는다.

6.2 합성(샘플) 데이터

허브 API 응답과 같은 컬럼으로 만든 시드 고정 합성 데이터(시드 20261119, 2023-11~2026-10)다. 실데이터와 같은 적재 경로를 지나고, 읍면동마다 숨은 유형을 심어 세 단계가 끝까지 이어지는지 시험한다. 실제 통계가 아니므로 화면과 제안서에 "샘플 데이터" 배지가 붙는다. 골든셋 60문항의 기대값은 이 데이터로 에이전트와 다른 경로(pandas)에서 계산한다.
