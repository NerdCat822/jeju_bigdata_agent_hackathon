머물멍 결과 설명자료

사람이 떠나는 동네에 누가 오고, 어떻게 오게 할 것인가

제주 43개 읍면동의 청년 정착을 진단하고, 빈자리를 채울 관광객과 그들이 오는 길까지 제안하는 3단계 AI 에이전트를 만들었다. 제주데이터허브 실데이터 8종으로 43곳의 유형을 나누고, 표선면을 예로 세 단계와 최종 제안서까지 실행했다. 숫자는 SQL이, 제안은 규칙이 만들고, Claude는 검증을 통과한 쉬운 설명만 쓴다. 골든셋 60문항을 모두 맞혔다.

1문제 정의

1.1 같은 동네에서 맞물리는 세 가지 변화

제주는 세 가지 변화를 동시에 겪고 있다. 2023년 14년 만에 인구가 순유출로 돌아섰고, 2026년 상반기 내국인 관광객은 6.4% 줄었지만 외국인 관광객은 31.9% 늘었다. 같은 기간 국내선 공급석은 37만 석 줄었다 (기획서 1.1). 세 변화는 인구·관광·교통 분야에서 따로 분석되어 왔지만, 실제로는 같은 동네 안에서 맞물려 있다.

변화정책 질문담당 단계
청년이 떠난다어느 동네에서 청년이 빠지고 어디는 버티는가. 청년 정착 지원은 어디에 효과가 있을까1단계 「청년이 머무는 동네」
관광객이 바뀐다빈자리를 채우는 외국인 소비는 어느 업종·요일·국적에서 오는가2단계 「빈자리를 누가 채우나」
접근이 줄었다감편 조건에서 수요는 어떻게 변하고, 어떤 노선·코스로 동네까지 데려올 수 있는가3단계 「어떻게 오게 하나」

1.2 누가, 어떻게 쓰는가

이 질문들은 원래 데이터 분석가가 여러 자료를 맞춰 보고 SQL을 짜야 답할 수 있다. 머물멍은 IT 비전문가인 도민·소상공인과 읍면 담당자가 "성산읍 청년 인구 왜 줄었어?" 같은 한 문장이나 지도에서 동네 하나를 고르는 것만으로, 근거와 한계가 붙은 답과 제안서를 받게 한다. 제주빅데이터센터 분석실에 상시 탑재해 인터넷 없이도 돌아가는 것을 목표로 한다.

1.3 목표

목표내용
물으면 분석한다한 문장을 장소·기간·연령·업종·가정값으로 해석하고, 필요한 데이터를 골라 SQL로 계산한다
단계가 이어진다1단계의 유형(A~D)이 2단계의 질문을, 2단계의 타깃 관광객이 3단계의 입력을 정한다. 동네 하나만 고르면 최종 제안서까지 만든다
근거 없는 말은 하지 않는다숫자는 SQL이, 제안 후보는 규칙이 만들고 LLM은 해석과 문장만 맡는다. 모든 답에 근거표·SQL·기간·한계를 붙이고, 상관을 인과로 단정하지 않는다
센터에서 오프라인으로 돈다센터 PC에서 인터넷 없이 기본 모드로 돌고, Claude 모드와 같은 숫자를 낸다

2Agent 구조

2.1 구성 요소의 역할

구성 요소하는 일구현 (backend/meomulmeong/)
해석기규칙 파서가 단계·의도·장소·연령·기간·테마·가정값을 뽑는다. 장소는 참조표로 표준화한다(법환동 → 대륜동). 규칙으로 확신하지 못한 질문만 Claude에 JSON 스키마로 넘기고, Claude가 낸 장소도 참조표에 없으면 버린다agent/parser.py
확인 카드해석 결과를 칩으로 보여 주고, 읍면동이 빠졌으면 실행할 수 없다고 알린다. 사용자가 고친 값은 서버가 참조표로 다시 검사한다agent/parser.py · 화면 ConfirmCard
계획 · 실행단계별 레시피가 도구를 순서대로 부른다. 2·3단계에 앞 단계 결과(유형 → 타깃)가 없으면 먼저 실행한다agent/stages.py · tools/
검증기해설 문장을 숫자·짝·인과·예측·참조·제안 근거·기간·반출 기준으로 검사한다. 떨어지면 고칠 점을 알려 최대 2회 다시 쓰게 하고, 그래도 떨어지면 규칙 문장으로 바꾼다agent/verifier.py
해설기지표만으로 만드는 규칙 문장(초안)을 쓰고, Claude 모드에서는 초안과 지표를 주고 3문장 이내로 다듬게 한다. 한 줄 결론과 목록형 답은 규칙 문장을 그대로 쓴다agent/explainer.py
기억세션마다 앞 질문의 장소·단계·결과를 기억해 "거기 30대만?" 같은 후속 질문과 단계 연계를 잇는다agent/memory.py
제안서세 단계의 답을 위치 지도(네이버 Static Map 또는 SVG), 근거표, SQL, 한계와 함께 HTML 한 장으로 묶는다report/builder.py

3주요 기능

기능내용
세 단계 분석과 연계 실행동네 하나를 고르고 "처음부터 끝까지"를 누르면 1→2→3단계를 차례로 돌리고 최종 제안서를 만든다. 어느 단계부터 물어도 앞 단계가 필요하면 먼저 실행한다
타이핑 없이 시작단계별 추천 질문, 읍면동 목록, 네이버 지도에서 누르기(누른 자리의 행정동을 찾음), 주소로 찾기
확인 카드직접 쓴 질문은 "이렇게 이해했어요"로 장소·연령·기간·테마·가정값을 먼저 보여 주고, "고치기"로 바꿔 실행한다
진행 표시 · 멈추기단계·도구·설명 쓰기를 한 줄씩 보여 준다(SSE). 멈출 수 있고, 다른 사람의 분석을 기다리는 중이면 그렇다고 표시한다
결론부터 보여 주는 답한 줄 결론 → 핵심 숫자 3개 → 쉬운 설명 → 제안 → 차트(표로 보기)·지도. 유형은 글자와 색을 함께 쓴다
근거 공개모든 숫자의 근거표와 실행한 SQL, 산식, 자료 기간, 한계, 검증 결과, 실행 기록(도구·시간·LLM 시도)을 펼쳐 볼 수 있다
전송 미리보기와 동의Claude에 보낼 집계 지표와 초안을 그대로 보여 주고, 동의한 세션만 보낸다
규칙 기반 제안제안은 설정 파일의 규칙 12개에서만 나오고, 규칙 번호와 근거 지표(기준값 포함)를 함께 보여 준다
감편 시나리오국내선 공급 변화율과 탄력성 ε를 가정으로 입도객을 계산하고, ε 0.5·1.0·1.5 민감도와 "가정" 배지를 늘 함께 보여 준다
코스와 접근성 공백거점 6곳에서 직행·환승 1회로 동네까지 오는 버스 코스를 네이버 길찾기 도로 경로로 그리고, 닿지 않는 거점을 공백으로 표시한다
최종 제안서세 단계의 결과·근거표·SQL·한계를 위치 지도와 함께 HTML로 묶는다. 인쇄하면 PDF가 된다
데이터 모드 · 명령줄샘플·실데이터·센터 데이터를 같은 경로로 쓴다. 명령줄(ask, chain --report)과 Python API도 있다

5.5 한계

데이터 유동인구는 통신 데이터 추정치이고, 허브 쿼터 때문에 달마다 며칠만 받아 하루 평균으로 계산한다. 중국인 카드(1048)는 제주 전체 단위라 2단계가 읍면동 차이를 반영하지 못한다 (센터 카드 v02로 풀 수 있다, 6장). 요일별 카드와 단체/개별 소비는 2016~2017 자료뿐이라 기간을 함께 적는다. 버스 노선 참조표는 샘플이라 3단계의 코스와 노선 민감도는 방법을 보여 주는 수준이다. 좌표와 지구 연결은 잠정값이다.
방법 상관만 보고 인과를 단정하지 않는다. 시나리오는 예측이 아니라 가정(감편률·탄력성)에 따른 계산이다. 유형 경계(τ = 3%) 근처의 동네는 기준값에 따라 유형이 바뀔 수 있어, 유지형에는 가장 가까운 유형을 함께 보여 준다. 노선이 적은 동네는 관광 민감 노선이 없게 나올 수 있다 (표선면 4개 중 0개).
AI 검증기는 숫자가 없는 문장의 뜻 바뀜과 최상급 낱말 없이 덧붙인 평가까지는 잡지 못한다. 골든셋 전체를 Claude 모드로 돌리지는 않았다 (요금). 목록이 들어가는 답은 Claude 모드에서도 규칙 문장을 쓴다.
운영 로그인 기능이 없고 분석은 한 번에 하나다. 대화 맥락은 서버 메모리에만 있다. 센터 모드는 명세서로만 만들었고 실제 추출본으로 검증하지 않았다. 센터용 설치 스크립트가 아직 없다.

  • 인터넷 없이 기본 모드로 돈다. 화면은 미리 빌드한 frontend/dist를 옮기고, Python 3.11과 PostgreSQL만 있으면 된다. GPU는 쓰지 않는다.
  • 센터 추출본을 backend/data/center/에 넣고 build-data --mode center를 실행하면 같은 표준 테이블로 적재되고, 센터 자료가 없는 표는 허브 자료로 채운다.
  • 새 테이블은 설명 파일(YAML) 한 장, 제안 규칙은 playbook.yaml, 기준값은 settings.yaml을 고쳐 반영한다. 개발자 없이 센터 담당자가 관리할 수 있다.
